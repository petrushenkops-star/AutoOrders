# MAX Автосигналы 0.3.9 — получение кодов из истории чата

## Новый источник: официальный MAX Bot API

Получение кодов из уведомлений исключено. Приложение опрашивает историю «ЛюменХ» через `GET /chats/{chatId}` и `GET /messages`, используя токен официального бота-администратора, добавленного в чат с правом `read_all_messages`. Имя чата дополнительно проверяется по серверному ID. Токен вводится в приложении и хранится зашифрованным ключом Android Keystore. Токен нельзя публиковать в репозитории.

**Для подключения нужны:** зарегистрированный MAX-бот (создание доступно после верификации организации/ИП/самозанятого), назначение бота администратором чата «ЛюменХ» с правом чтения всех сообщений, его токен и `chat_id`. Без этого API не сможет читать историю личного пользователя.

### Поведение

- На вкладке «Настройки» ввести токен и `chat_id`, сохранить, нажать «Проверить историю MAX (БЕЗ заказа)». Эта кнопка никогда не создаёт и не отправляет заказ.
- Установить окно поиска сообщений HH:mm–HH:mm и длину кода; окно, пересекающее полночь, поддерживается. Начало равно окончанию — с полуночи сегодня.
- Во время открытого приложения на вкладке «Сайт» при включённых обеих опциях проверка выполняется каждые 45 секунд. Если найден один новый однозначный код не старше пяти минут, он поступает в ранее проверенный алгоритм оформления заказа. Когда приложение закрыто или заблокировано, этот этап не работает — это будет отдельная задача.
- При нескольких разных кодах за период, ошибке доступа, устаревшем коде, отсутствии однозначного подтверждения сайта или переполнении выборки автоматический заказ не запускается.
- Сценарий оформления и проверка статуса «В ожидании» из 0.3.8 не изменены. Ручной ввод сохранён.
- После использования кода другой заказ с тем же кодом за текущие сутки не отправляется. При неизвестном результате автоматический повтор заблокирован.

**Проверка с реальным MAX API невозможна без токена бота и id чата.** Не отправляйте токен в ChatGPT. В GitHub Actions собирается подписанный APK с тем же applicationId и сертификатом, что и версии 0.3.x.

Официальная документация: https://dev.max.ru/docs-api/methods/GET/messages и https://dev.max.ru/help/chatbots

## v0.3.8 — диагностика получения кода MAX

- Исправлен разбор групповых уведомлений: название чата может приходить в `EXTRA_CONVERSATION_TITLE`, `EXTRA_SUB_TEXT`, `EXTRA_TITLE_BIG` или `EXTRA_TITLE`; текст — в том числе через `EXTRA_MESSAGES`.
- Добавлены два индикатора: подключение службы и время последнего системного уведомления MAX. В журнале показывается конкретная причина отказа, без записи кода или содержимого чата.
- Первый тест без финансовой операции: в «Настройки» включить получение сигналов, отключить автоматическое оформление, открыть доступ к уведомлениям, свернуть MAX, попросить **другого участника** отправить новое сообщение с кодом в чат «ЛюменХ».
- Если уведомления самого MAX нет в шторке Android, приложение не сможет принять код. Проверьте разрешения MAX и уведомления конкретного чата.
- Для чтения сообщений **из собственного аккаунта** через локальный NotificationListenerService нельзя рассчитывать на сообщения, которые были отправлены с этого же аккаунта: MAX может не создавать для них уведомления.
- Распознавание безопасное: сообщения из чужих чатов не запускают финансовые операции. Ручной ввод и существующий сценарий заказа не менялись. Подтверждение новой автоматизации на реальном сайте остаётся необходимым.

## Автономность при заблокированном экране

**Полностью автономный режим пока НЕ реализован.** Слушатель Android может получать уведомления MAX при блокировке телефона, когда Android их доставляет и содержимое доступно. Но Android ограничивает запуск экрана и WebView из фона. Поэтому на устройстве с закрытым приложением нельзя гарантировать вход на сайт и отправку заказа.

Для надежной автоматизации без разблокировки требуется документированный торговый API сайта и разрешенный доступ к нему. Тогда движок может выполнять один запрос и проверять фактический статус заказа, не открывая страницу. Без API обещать выполнение на заблокированном телефоне нельзя. Недопустимо обходить экран блокировки, хранить PIN телефона и имитировать биометрию.

Безопасный протокол: принять код из доверенного чата, проверить время и свежесть, зарегистрировать попытку до отправки, выполнить один запрос, сверить результат. Если статус неизвестен, не повторять финансовую операцию автоматически. Секреты доступа не вшивать в APK.

## Как тестировать

1. Для установки используйте ТОЛЬКО постоянным ключом подписанный release APK из GitHub Releases. Debug APK не обеспечивает последующих обновлений подписанного релиза.
2. Установите APK и сохраните настройки длины кода. На первом этапе вводите код вручную на вкладке «Сайт»; название чата MAX пока не требуется.
3. Разрешения MAX для ручного ввода не нужны. Сначала авторизуйтесь на сайте в браузере приложения.
4. Вставьте новый код и нажмите «Выполнить заказ по введённому коду». Приложение выполнит последовательность по DOM-сценарию.
5. Не тестируйте реальные финансовые операции до проверки шагов на вашем аккаунте. Если статус неизвестен, не выполняйте повтор.
6. Коды из MAX можно подключить позднее: владелец чата подтвердил возможность доступа, но на этом этапе он не требуется.
7. При обновлениях устанавливайте новый подписанный APK поверх старого, не удаляя приложение.

## Защита от повторного заказа

Отпечаток кода записывается **до** браузерной автоматизации. Если приложение закрылось,
подтверждение зависло или статус неизвестен, сигнал не отправляется повторно автоматически.
Пароли и cookies сайта не копируются и не передаются во внешние сервисы. Сам код хранится
только короткое время в закрытых настройках приложения и в памяти во время обработки.

## Нужно уточнить для полного завершения

- Пример реального сообщения с кодом из MAX (без личной переписки и конфиденциальной информации).
- Название чата и точное разрешённое временное окно.
- Подтверждено: должна работать при заблокированном экране; для этого нужен разрешенный интерфейс торговых заявок без WebView.
- Нужно подтвердить последовательность элементов **на реальном сайте**, поскольку видео не показывает их DOM.

Без этих данных нельзя честно считать торговый робот полностью проверенным.

## Постоянная подпись (обязательна для обновления)

В Actions выполняются два отдельных этапа: компиляция и подписанная release-сборка.
Для подписи секрет `AUTOORDERS_SIGNING_BUNDLE` распаковывается ВО ВРЕМЯ сборки;
ключ никогда не включается в исходный код или архив проекта.
Для будущего обновления **сохранить тот же applicationId и секрет**, увеличить
`versionCode`, `versionName` и выпускать только подписанный release APK.

Если переносите проект в другой репозиторий, необходимо подключить тот же
закрытый ключ с тем же паролем и alias. Иначе Android потребует удалять
приложение перед установкой.

## Исправление по видеозаписи 7754.mp4 (версия 0.3.4)

На записи первоначальный сценарий останавливался на рекламном модальном
окне LUMEN X: до ручного закрытия окна и перехода в «Торговля» приложение
не могло продолжить. После ручного перехода ввод динамического кода,
подтверждение и проверка успешного результата выполнялись автоматически.

Что изменено:
- В начальном состоянии распознаётся только рекламное окно с заголовком
  LUMEN X; нажимается только его крестик в правом верхнем углу.
- После закрытия модального окна процесс продолжает ожидание, не нажимая
  торговые кнопки под видимой рекламой.
- Вкладка «Торговля» теперь распознаётся как пункт нижней панели
  сайта, даже если она размечена как `div` / `span`, а не `button`.
- После одного перехода в раздел приложение дожидается появления
  «Быстрого копирования» без повторного нажатия на вкладку.
- Сохранена однократность финансового подтверждения, защита от
  неопределённого результата и запрет автоматического повторения.
- Добавлены автономные тесты: реклама, нижняя панель, смена
  страниц, неоднозначные элементы, однократное подтверждение.

**Важно:** исправление подтверждено только симуляцией DOM. Живой сайт
может изменять разметку. До подтверждения на телефоне нельзя считать
все действия полностью автоматизированными. Не выполняйте серию реальных
заказов для проверки; используйте безопасный тест или один
контролируемый проход, если его разрешает площадка.

Версия 0.3.4 также исправляет критичный ложноположительный успех:
оставшееся на странице сообщение об успехе предыдущего заказа больше
не считается успехом новой операции. Для текущей операции успех
распознаётся только после её однократного подтверждения. После успешной
операции окно результата закрывается автоматически, если единственная
кнопка подтверждения однозначно распознана.

## Изменение 0.4.7 — диагностика запуска
При попытке вручную выполнить заказ приложение различает повторное использование кода за сегодня, активную операцию и ожидающий сигнал. ## v0.4.8 — Background continuation for an active order

A manually/explicitly triggered browser order is protected by an Android
`shortService` foreground service with a persistent notification, a STOP action,
and a bounded partial wake lock (165 s). The existing WebView and driver state
are retained during Activity pause/recreation. The service never begins a new
order, and a killed process never auto-retries an order with unknown outcome.

Android's `shortService` limit is ~3 minutes; this release is for **one
in-progress trade only**, not long-running weekly Telegram schedule checks.
The latter still need a separate durable scheduler/worker architecture.
WebView pages may still behave differently on individual device vendors while
backgrounded; on-device verification is required before assuming reliability.
