# Автозаказы (AutoOrders)

Android-приложение для расписания заказов на lxcompintb.com. Автоматизация реальных финансовых операций не подтверждена тестами на живом сайте.

## Постоянная подпись (начиная с 0.1.11)

**Подпись:** SHA-256 `ED:F5:BA:9D:66:32:E9:4F:BB:80:27:1D:44:77:75:E3:1B:C1:7B:0F:5C:59:58:92:3B:AB:1B:B9:BF:01:BA:69`.

Один раз создать Actions secret **`AUTOORDERS_SIGNING_BUNDLE`** и вставить в поле Secret значение из личного файла `AutoOrders-GitHub-Secret.txt`. Этот секрет содержит постоянный PKCS12-keystore, пароль и псевдоним ключа. Никогда не добавлять его в репозиторий, чат или issue. Сохранить отдельно резервную копию signing key.

GitHub Actions workflow `Build AutoOrders` тестирует проект и собирает debug-версию. При наличии указанного секрета он также собирает release APK, проверяет SHA-256 сертификата и публикует `AutoOrders-<version>-signed.apk` в Releases.

Чтобы запустить после добавления секрета: Actions → Build AutoOrders → Run workflow. Для каждого нового выпуска повышать **versionCode и versionName** в `app/build.gradle.kts`. Файлы существующих релизов не перезаписываются.

**Однократный переход:** APK до 0.1.10 подписаны автоматически созданным отладочным ключом среды сборки. Обновить их поверх без исходного старого ключа, вероятно, невозможно: потребуется **один раз удалить установленную версию**, что приведёт к потере локальных настроек. Начиная с установленного APK 0.1.11 с постоянной подписью, будущие версии с тем же ключом и повышенным versionCode смогут обновляться без удаления.

**Не теряйте секрет/резервную копию ключа:** иначе новые APK нельзя будет установить поверх существующих.

## Версия 0.1.12 — безопасный статус незавершённого заказа

- Пока идёт выполнение, запись имеет статус «Выполняется» и не попадает в ожидающие нового кода.
- Если приложение завершилось во время обработки, после перезапуска запись становится «Результат неизвестен», а не «Ошибка». Перед новой попыткой нужно проверить итог на сайте.
- Если автоматизация могла отправить подтверждение, остановка, тайм-аут или неоднозначный ответ сайта также дают статус «Результат неизвестен». Автоматический повтор не выполняется.
- Номер версии на экране теперь берётся из параметров установленной APK.
- Постоянный сертификат и формат локального хранилища сохранены; версия подготовлена для проверки обновления поверх 0.1.11 без удаления.

## Версия 0.1.13 — проверка перекрытого окна подтверждения

- Подъём окна над затемнением выполняется с запасом в три уровня, поскольку сайт может поднять overlay после перерисовки.
- Через секунду после исправления приложение повторно проверяет, остаётся ли кнопка доступной, и показывает понятный результат.
- Автоматическое нажатие финансового подтверждения через JavaScript теперь запрещено, если кнопка фактически закрыта другим элементом или находится вне экрана.
- Никакие действия по размещению окна и диагностике сами по себе не отправляют заказ.
- Подпись APK и локальные данные сохраняются при обновлении поверх 0.1.12.

## Версия 0.1.14 — диагностика вложенных слоёв WebView

- После неудачного «Показать окно» временные изменения CSS отменяются и автоматически выполняется только чтение структуры слоёв страницы.
- Отчёт показывает отношение окна и затемнения, признаки независимых контекстов наложения, типы и z-index родительских контейнеров, глубину вложенности и порядок слоёв в точке кнопки.
- Диагностика не читает коды, суммы заказа, данные учётной записи и не нажимает элементы сайта.
- Это диагностическая сборка; новое исправление отображения будет выбрано по результату на устройстве.
- Подпись для обновлений сохранена, versionCode увеличен.

## Версия 0.1.15 — исправление порядка отображения окна

- По диагностике 0.1.14 окно подтверждения и затемнение являются соседними элементами с одинаковыми уровнями наложения.
- Если безопасные изменения z-index не помогают, приложение пробует переставить **существующее** окно после затемнения в DOM, чтобы изменить порядок отрисовки.
- При неудаче первоначальный порядок элементов восстанавливается. Отправка заказа и нажатия не выполняются.
- Через одну секунду проверяется доступность кнопки. Это экспериментальное визуальное исправление, не проверенное на реальном устройстве.
- Прежняя подпись и локальные настройки сохранены.

## Версия 0.1.16 — офлайн-симулятор

- В разделе «Сайт» добавлена кнопка «Офлайн-симулятор — без реальных заказов».
- Отдельный WebView загружает локальную страницу со сценариями «Успех», «Ошибка» и «Нет ответа».
- Можно воспроизвести видимое и перекрытое окно подтверждения. Кнопки «Проверить» и «Показать окно» используют общие модули диагностики и исправления.
- Автоматический прогон использует реальный алгоритм `SiteRunner` и `driver.js`, но работает только при включённом тестовом режиме, тестовом origin и маркере страницы.
- Фиктивный код `123456` не отправляется в интернет. WebView запрещает внешние сетевые запросы и переходы, а тестовые результаты не записываются в журнал реальных заказов.
- Сценарии и проверки изоляции запускаются в CI автоматически.
- Это симуляция, а не копия живого сайта: окончательные результаты реальных заказов по-прежнему необходимо проверять отдельно.

## Версия 0.1.17 — исправлен null в офлайн-симуляторе

- Команды «Проверить», «Показать окно» и повторный автоматический запуск больше не объявляют общую глобальную JavaScript-переменную; каждый вызов выполняется в собственной области видимости.
- При отсутствии ответа показывается понятная ошибка вместо null.
- Добавлены офлайн-тесты многократных вызовов диагностических скриптов и драйвера в одном контексте JavaScript.
- Сетевая изоляция симулятора, работа реального сайта и постоянная подпись APK не изменены.

## Версия 0.1.18 — быстрый доступ к тестовому окну

- В офлайн-симуляторе появилась кнопка «Открыть тестовое окно»: сразу показывает подтверждение без цифрового кода и промежуточных шагов.
- Кнопка «Показать окно» переименована в «Исправить перекрытие», чтобы не путать открытие окна с попыткой изменения слоёв.
- Если окно не открыто, диагностика объясняет, что нужно нажать, вместо технического `not_found`.
- Режимы «Видно» и «Перекрыто» сохраняются при прямом открытии, добавлены тесты обоих вариантов.
- Встроенный браузер реального сайта не меняется; симулятор по-прежнему работает без сетевых запросов и реальных заказов.

## Функциональность

Недельное расписание, ручной ввод нового кода перед каждым заказом, журнал заказов, встроенный браузер и диагностический режим. Работа с реальными финансовыми заказами экспериментальная.
